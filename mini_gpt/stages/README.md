# نسخه‌های تدریجی، نه ۹ پروژهٔ جدا

## ۲۳ ایستگاه؛ هر بار یک جزء را بررسی کنید

در کنار نسخه‌های v0 تا v8، مسیر «ایستگاه‌ها» را داریم تا هر بار اثر یک جزء را جدا ببینیم. شمارهٔ ایستگاه با شمارهٔ نسخه یکی نیست. هر ایستگاه یکی از اجزای همان پروژه را روی متن ثابت و کوتاه اجرا می‌کند؛ شکل و مقدار خروجی را می‌توانید بررسی کنید. دستور را از ریشهٔ پروژه بزنید:

```sh
python -m mini_gpt.milestones --stage 6
python -m mini_gpt.milestones --stage 10 --output runs/milestone-10.json
python -m mini_gpt.milestones --stage 16 --checkpoint runs/milestone-16.pt --output runs/milestone-16.json
```

JSON قالب متنی داده است. مسیر خروجی اختیاری است و باید تازه باشد؛ برنامه فایل قبلی را بازنویسی نمی‌کند. از ایستگاه ۱۶ به بعد می‌توان فایل واقعی وزن را با `--checkpoint` نگه داشت؛ بدون این گزینه ذخیره/بارگذاری در فایل موقت آزموده می‌شود و سپس آن فایل پاک می‌شود. این Checkpoint با دادهٔ ساختگی برای بازرسی و تولید قابل استفاده است، اما برای ادامهٔ آموزش روی پیکره ساخته نشده است؛ برای resume از فرمان اصلی train استفاده کنید.

| ایستگاه | خروجی قابل لمس | سؤال پیش از اجرا |
|---:|---|---|
| ۰ | شمارش ادامهٔ هر شناسه، بدون PyTorch | کدام ادامه هرگز دیده نشده است؟ |
| ۱ | رفت‌وبرگشت Tokenizer و مثال Unknown token | کاراکترِ ندیده چطور بازمی‌گردد؟ |
| ۲ | واژگان، شناسه‌ها و بازسازی متن | آیا بزرگی شناسه معنی زبانی دارد؟ |
| ۳ | بردارهای Embedding با شکل `(1,8,16)` | Token تکراری چه برداری دارد؟ |
| ۴ | Positional Embedding و جمع آن با Token Embedding | نمایش یک Token در دو جایگاه هنوز برابر است؟ |
| ۵ | Attention با یک Head، عمداً بدون Mask | وزن نگاه به آینده صفر است؟ |
| ۶ | همان سازوکار با Causal Mask | قطر چرا مجاز می‌ماند؟ |
| ۷ | وزن‌های دو Head موازی | کدام محور، Headها را جدا می‌کند؟ |
| ۸ | خروجی FFN برای هر موقعیت | این جزء اطلاعات موقعیت‌ها را با هم ترکیب می‌کند؟ |
| ۹ | جمع ورودی و تغییر پیشنهادی | اگر تغییر صفر شود، ورودی چه می‌شود؟ |
| ۱۰ | میانگین/واریانس سطرهای نرمال‌شده | چرا واریانس دقیقاً یک نیست؟ |
| ۱۱ | خروجی یک بلوک واقعی Pre-Norm | شکل بیرونی کجا تغییر می‌کند؟ |
| ۱۲ | خروجی دو بلوک پشت سر هم | پارامترها مشترک‌اند یا جدا؟ |
| ۱۳ | Logits مربوط به Vocabulary و Loss | چرا امتیاز خام، احتمال نیست؟ |
| ۱۴ | Loss قبل و بعد از ۲۰ به‌روزرسانی یک Batch | آیا حفظ یک دسته نشانهٔ تعمیم است؟ |
| ۱۵ | Loss دادهٔ ساختگیِ کنارگذاشته‌شده | آیا وزن‌ها هنگام سنجش عوض می‌شوند؟ |
| ۱۶ | برابری وزن پس از ذخیره/بارگذاری | آیا نگاشت Tokenها همراه وزن است؟ |
| ۱۷ | چهار Token پیاپی با انتخاب Greedy | برای Token دوم چه ورودی‌ای می‌دهیم؟ |
| ۱۸ | احتمال انتخاب و یک نمونه | دو اجرا با بذر یکسان چه می‌کنند؟ |
| ۱۹ | Temperature برابر ۰٫۵ روی Logits همان مدل | آیا توزیع احتمال متمرکزتر می‌شود؟ |
| ۲۰ | فقط سه نامزد با احتمال غیرصفر | آیا سه گزینه، هم‌احتمال‌اند؟ |
| ۲۱ | نامزدهای Top-p با آستانهٔ ۰٫۷ | آیا تعداد نامزد همیشه ثابت است؟ |
| ۲۲ | مدل کامل، شمار پارامتر و پیشنهاد اجرای واقعی | اکنون دادهٔ خودمان را کجا وصل کنیم؟ |

این ایستگاه‌ها با قطعه‌های مشترک `attention.py`، `transformer.py`، `model.py` و `sampling.py` کار می‌کنند. حلقهٔ کوچک از ایستگاه ۱۴ به بعد فقط ۲۰ بار یک دستهٔ ثابت را به‌روزرسانی می‌کند تا نتیجه فوری دیده شود؛ دادهٔ اعتبارسنجی آن نیز ساختگی و بسیار شبیه است. عدد حاصل ادعای کیفیت زبان یا تعمیم ندارد. پس از مشاهده، پروژه را با فرمان train روی متن خودتان آموزش دهید. وزن میان فرمان‌های ایستگاه خودکار منتقل نمی‌شود: هر فرمان ورودی و بذر ثابت را از نو می‌سازد تا مقایسه قابل تکرار باشد. هدف پیوستگیِ کد و مفهوم است، نه ادعای سازگاری وزن‌های معماری‌های متفاوت.

برای حرکت فعال، اول پاسخ سؤال ستون سوم را بنویسید، سپس خروجی را ببینید و تنها یک عدد/جزء را تغییر دهید. همهٔ ۲۳ ایستگاه در آزمون خودکار اجرا می‌شوند؛ مثلاً مجموع وزن آینده در ایستگاه ۵ مثبت و در ۶ صفر است.

## نسخه‌های قبلی، همچنان قابل اجرا

همهٔ فرمان‌ها از ریشهٔ پروژه اجرا می‌شوند. «نسخه» یعنی یک مرحلهٔ آموزشی با یک تفاوت اصلی؛ لازم نیست کتابخانه‌ها و ابزارهای مشترک را نه بار کپی کنیم.

| نسخه | تغییر اصلی نسبت به قبل | چه چیزی هنوز ندارد؟ | شناسهٔ درس؛ نه شمارهٔ نمایشی جلسه |
|---|---|---|---|
| v0.py | جدول شمارش جفت کاراکتر؛ فقط Python | نمایش یادگرفتنی و زمینهٔ بلند | `03-counts` |
| v1.py | جدول Embedding و تبدیل آن به Logits | ترکیب اطلاعات موقعیت‌های دیگر | `25-embedding` |
| v2.py | Attention با یک Head و Query، Key و Value | محدودیت آینده؛ عمداً نمونهٔ معیوب | `32-self` |
| v3.py | Causal Mask روی همان Head | چند Head موازی و اطلاعات موقعیت | `33-mask` تا `34-causal-test` |
| v4.py | Multi-Head Attention و Positional Embedding | FFN و دو Residual Connection | `35-split-heads` تا `36-merge-heads` |
| v5.py | جایگزینی لایهٔ Attention با یک Transformer block کامل | چند بلوک و نرمال‌سازی نهایی | `40-block` |
| v6.py | معماری نهایی با دو بلوک در تنظیم کوچک | ابزار اجرای آموزش واقعی | `41-stack` تا `46-gradient-path` |
| v7.py | رابط آموزش/ارزیابی/ذخیره/ادامهٔ مدل نهایی | فرمان تولید مستقل | `47-loop` تا `53-curves` |
| v8.py | فرمان تولید از Checkpoint | امکانات صنعتی؛ عمداً خارج از هدف | `54-generate` تا `62-journal` |

در v1، آخرین Token به‌تنهایی کافی است؛ این نسخه از نظر اطلاعات در دسترس هنوز زمینهٔ بلندی ندارد. v2 به آینده نگاه می‌کند؛ برای نشان‌دادن عیب است، نه آموزش مدل علّی معتبر. v3 فقط همین عیب را اصلاح می‌کند. v4 و v5 برای خوانایی از قطعه‌های توضیح‌داده‌شدهٔ attention.py و transformer.py استفاده می‌کنند. v6 کلاس نهایی را با تنظیم کوچک می‌سازد. v7/v8 پوستهٔ همان ابزار نهایی‌اند؛ وزن‌های هر نسخه خودکار به نسخهٔ بعد منتقل نمی‌شوند، چون معماری عوض شده است.

```sh
python -m mini_gpt.stages.v0
python -m mini_gpt.stages.run --stage 1
python -m mini_gpt.stages.run --stage 2
python -m mini_gpt.stages.run --stage 3
python -m mini_gpt.stages.run --stage 4
python -m mini_gpt.stages.run --stage 5
python -m mini_gpt.stages.run --stage 6
python -m mini_gpt.stages.v7 --text data/sample.txt --output runs/stage7 --steps 20 --context-length 16 --embedding-dim 16 --num-heads 2 --num-layers 1 --batch-size 8 --eval-every 10
python -m mini_gpt.stages.v8 --checkpoint runs/stage7/best.pt --prompt "مدل " --tokens 40 --top-k 10
```

مراحل ۱ تا ۶ امتیازهای یک ورودی ساختگی را محاسبه می‌کنند و اثر تغییر آینده بر گذشته را می‌سنجند؛ این‌ها آموزش متن واقعی نیستند. v2 باید تغییر گذشته نشان دهد؛ v1،v3،v4،v5،v6 در حالت ارزیابی نباید. v1 بدون Attention نیز آینده را نمی‌بیند؛ بنابراین «عدم نشت» به‌تنهایی کافی‌بودن معماری برای زبان را ثابت نمی‌کند.

قبل از بازکردن فایل هر مرحله، تغییر آن را خودتان در نسخهٔ تمرینی جدا بسازید. سپس شکل‌ها و نتیجه را با مرجع مقایسه کنید. برای حلقهٔ آموزش نسخهٔ اول می‌توانید از درس `47-loop` شروع کنید؛ خروجی v1 تا v5 فقط logits است، پس loss را بیرون مدل با F.cross_entropy محاسبه کنید. v6 جفت `(logits, loss)` می‌دهد و targets اختیاری است. این تفاوت قرارداد را از نظر دور نکنید.
